# 高危操作代码检验规范

> 版本：v1.0（2026-11）
> 适用范围：数据开发代码中的破坏性 SQL/DDL（ClickHouse / PostgreSQL / MySQL 及通用 SQL）与脚本中的破坏性命令。
> 目标：在代码评审（人工或 AI）环节拦截"全表更新、删库删表、分区销毁、权限变更"等高危操作，防止未审批的破坏性变更到达生产。
> 配套：检测引擎 `agents/sql-danger-reviewer/tools/danger_tools/danger_scan.py`；对抗加固 `agents/sql-danger-adversary/`（10 轮迭代报告见其 `reports/`）。

## 1. 风险分级

| 级别 | 含义 | 处置 |
|------|------|------|
| 【致命】 | 数据不可逆丢失或全表改写：无 WHERE 的 UPDATE/DELETE、DROP DATABASE、非豁免 DROP TABLE、tautology 条件 | 一票否决：禁止合入；必须走变更审批 + 备份 + 回滚预案 |
| 【高危】 | 大范围破坏或对象级损失：TRUNCATE、ALTER DROP COLUMN/PARTITION、ClickHouse mutation、动态拼出的破坏语句、GRANT ALL | 阻断合入，需 DBA 复核 + 明确授权标记 |
| 【中危】 | 有条件破坏或影响可控：RENAME/EXCHANGE 表、非键条件的批量 UPDATE/DELETE、OPTIMIZE FINAL 大表 | 评审确认影响面与窗口 |
| 【提示】 | 豁免路径（tmp 表清理）、注释/字面量中的危险词、EXPLAIN 演示 | 提示人工确认，不阻断 |

## 2. 检验规则（DGR-xxx）

### 2.1 致命类

| 规则 | 触发 | 例外（降级） |
|------|------|--------------|
| DGR-101 无 WHERE 的 DELETE | `DELETE FROM t`（无 WHERE 或 WHERE 为恒真） | 有非恒真 WHERE → 放行至中危评估（DGR-203） |
| DGR-102 无 WHERE 的 UPDATE | `UPDATE t SET ...`（同上） | 同上 |
| DGR-103 恒真条件（tautology） | WHERE 仅含：`1=1`、`true`、`'t'`、`id IS NOT NULL`、`id IN (SELECT id FROM 同表)`、`LIKE '%'` | 出现任一真值过滤（`= 值`、`IN (字面量)`、范围比较）即视为有守卫 |
| DGR-104 DROP DATABASE/SCHEMA | 含 `CASCADE` 一律致命 | 无（生产禁用） |
| DGR-105 DROP TABLE（非豁免名） | 表名不以 `tmp_`/`_staging` 开头且无 `-- safe:` 标记 | `DROP TABLE IF EXISTS tmp_*` / `tmp_*` / `_staging*` → 提示级豁免 |

### 2.2 高危类

| 规则 | 触发 |
|------|------|
| DGR-201 TRUNCATE TABLE | 任何 TRUNCATE（含 `TRUNCATE t` 简写） |
| DGR-202 ALTER 破坏性子句 | `DROP COLUMN`、`DROP PARTITION`、`DETACH PARTITION`、`MODIFY COLUMN`（截断风险）、`DROP CONSTRAINT` |
| DGR-203 非键条件的批量 UPDATE/DELETE | 有 WHERE 但条件列疑似非唯一键（无 `id`/`_id`/`_key` 等值判断）→ 中危起步，窗口期外升高危 |
| DGR-204 ClickHouse mutation | `ALTER TABLE ... DELETE/UPDATE`（重写整个 part，禁止常规 API） |
| DGR-205 动态拼装的破坏语句 | 应用代码 f-string/字符串拼接/`EXECUTE IMMEDIATE`/`PREPARE`/`cursor.execute` 中含破坏关键字 |
| DGR-206 权限变更 | `GRANT ALL`、`GRANT ... TO PUBLIC`、`REVOKE` |

### 2.3 中危类

| 规则 | 触发 |
|------|------|
| DGR-301 RENAME/EXCHANGE TABLES | 对象级替换，影响下游引用 |
| DGR-302 无事务包裹的破坏操作 | 致命/高危操作未在显式 `BEGIN ... COMMIT/ROLLBACK` 内 |
| DGR-303 大表 OPTIMIZE ... FINAL / VACUUM FULL | 重操作，需窗口 |

### 2.4 提示类

| 规则 | 触发 |
|------|------|
| DGR-401 豁免名 DROP | `tmp_`/`_staging` 前缀或 `IF EXISTS tmp_*` |
| DGR-402 字面量/注释中的危险词 | `SELECT 'DROP TABLE x'`、`-- TODO DROP`：不执行，提示人工确认非动态拼接 |
| DGR-403 EXPLAIN 前缀 | `EXPLAIN DELETE ...` 不实际执行（PG/CK），提示确认未被封装执行 |

### 2.5 脚本类（代码中混排的命令）

| 规则 | 触发 |
|------|------|
| DGR-501 `rm -rf`（尤其 `/`、`~`、无引号变量路径） | 致命 |
| DGR-502 `clickhouse-client`/`psql`/`mysql` `-q/--query` 直连执行破坏语句 | 高危 |

## 3. 对抗（混淆）对策——检验必须免疫的绕过手法

检测引擎在匹配前做**规范化**，以下手法不得造成漏报（每条都在对抗 Agent 的攻击技术库中）：

1. **大小写/空白混淆**：`dRoP  tAbLe` → 匹配统一 case-insensitive + `\s+`。
2. **注释注入**：`DR/**/OP TABLE`、`--x\nDROP` → 先剥离注释再匹配；同时"剥离出的注释内危险词"按 DGR-402 提示。
3. **标识符引用**：`` DROP TABLE `orders` `` / `"orders"` → 剥离引号反引号。
4. **恒真伪装**：`WHERE 1=1` / `WHERE true` / `WHERE id IS NOT NULL` / `WHERE id IN (SELECT id FROM t)` → 按"无守卫"判定（DGR-103）。
5. **CTE/子查询包裹**：`WITH g AS (SELECT 1) DELETE FROM t ...` → 语句级规则不受包裹影响。
6. **事务装饰**：`BEGIN; DROP TABLE x; COMMIT;` → 事务不降低破坏性（反而是 DGR-302 的加分项：有事务降一档但仍是原级别阻断——致命仍致命）。
7. **三明治掩埋**：破坏语句混在大量良性语句中间 → 按语句逐条扫描。
8. **动态拼装**：`cursor.execute(f"DROP TABLE {t}")`、`"TRUNCATE " + t`、`EXECUTE IMMEDIATE '...'`、`PREPARE ... FROM '...'`、`sp_executesql` → DGR-205。
9. **多语句单行**：`;` 分隔（含字符串内分号免疫）→ 正确切分。
10. **假阳性对抗**：良性语句长得危险（`SELECT 'DROP TABLE x'`、注释提及、`EXPLAIN DELETE`、tmp 豁免、带 id 等值的 UPDATE/DELETE）→ 不得误报阻断。

## 4. 豁免与放行机制

1. **命名豁免**：`tmp_` / `_staging` 前缀表的 DROP/TRUNCATE → 提示级。
2. **显式标记**：语句前置注释 `-- safe: <原因+工单号>` → 降一级并在报告中列出待人工核对。
3. **守卫判定**：WHERE 含键等值（列名含 `id`/`_key` 且用 `=` 或 `IN (字面量)`）→ 不触发致命类。
4. **审批流**：任何致命/高危 → `requires_approval = true`，报告输出"审批-备份-回滚-窗口"四件套要求。

## 5. AI 评审输出要求

1. 每条发现必须给出：规则号、级别、证据片段（原始文本，不规范化后的）、建议（改写或审批路径）。
2. 聚合结论：`verdict ∈ {block, review, pass}`；任一致命 → block。
3. 不得因语句数量多而截断漏报——全部语句扫完。
4. 对抗样本（混淆形态）与普通形态同等对待，不允许"看起来奇怪就报、看不懂就放过"。

## 6. 迭代验证（与对抗 Agent 的 10 轮联动）

每轮：对抗 Agent 按递进技术生成攻击集（含漏报攻击与误报攻击）→ 检测引擎全量评估 → 统计 检出率/误报率 → 未覆盖技术回补规则 → 下一轮。验收线：**第 10 轮检出率 100% 且误报率 0%**；过程与规则新增记录见 `agents/sql-danger-adversary/reports/iteration-report.md`。
